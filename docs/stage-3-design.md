# Этап 3: технический каркас

Основание: согласованная дорожная карта и поручение перейти к этапу 3.

## Подход

Выбранный ранее вариант — Luau + Rojo, сервер владеет состоянием. Клиентское владение прогрессом не подходит из-за возможности подменять награды. Подключение DataStore сейчас расширило бы работу до этапа 6, поэтому профили временно хранятся в памяти и сбрасываются при выходе.

## Границы

- Версионированный профиль: ресурсы, питомцы с уникальными ID, экипированные ID.
- Отдельное временное состояние команды: пока только Idle и отзыв.
- Один тестовый вид питомца, без согласования внешности или баланса.
- Серверные операции выдачи питомца и клиентские запросы GetState, EquipPet, UnequipPet, RecallTeam.
- Только свои данные в ответе; владелец определяется по Player, а не по переданному ID.
- Проверки типов, лишних полей, владения, лимитов, повторной экипировки и частоты запросов.
- Все изменения выполняются без yield, с защитой от повторного входа; будущие операции, которые ожидают сеть, нельзя помещать внутрь этой секции.
- Клиент получает копию состояния. Он не задаёт награды, ресурсы, вид или уровень питомца.

Технические значения, выбранные исполнителем: команда до 3, коллекция до 100, интервал запросов 0.15 с; один тестовый питомец уровня 1. Это не игровой баланс.

## Проверки

Чистые правила запускаются через Lune. Rojo проверяет сборку и размещение объектов. Реальные RemoteEvent, два клиента и запуск в Studio проверяются отдельно по инструкции. Новый рабочий MythicPets.rbxl сохраняется отдельно от двух старых тестовых плейсов.

## Не входит

Добыча, бой, кейсы, объединение, UI коллекции, DataStore, подбор баланса и финальные виды питомцев.
