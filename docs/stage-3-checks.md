# Этап 3: состояние и проверки

## Реализовано

- Сервер хранит временные профили с SchemaVersion = 1, ресурсами, коллекцией и ID команды.
- При входе выдаётся один тестовый питомец prototype с уникальным GUID, формой 1 и уровнем 1. Внешней модели питомца пока нет.
- Задача команды хранится отдельно от профиля; на этом этапе поддерживается только Idle.
- GetState, EquipPet, UnequipPet, RecallTeam проходят через серверную проверку. Неизвестные действия и лишние поля отклоняются.
- Клиент не передаёт владельца, награды или изменения ресурсов. Ответ получает только отправивший запрос игрок.
- Серверные операции не ожидают сеть и не уступают выполнение. Запросы ограничены интервалом 0.15 с на игрока; отклонённый из-за частоты запрос не получает ответа, чтобы не усиливать поток.
- Профили удаляются при выходе. Это MemoryOnly, не сохранение данных.
- Новый рабочий файл: MythicPets.rbxl. Карта сохраняется в Studio; код хранится в src и синхронизируется Rojo.

## Проверка в Studio

1. Открой MythicPets.rbxl. Запусти `rojo serve default.project.json` в папке проекта и подключи плагин.
2. Нажми Play. В Output ожидаются:

   ```text
   [Server] Stage 3 ready. Progress is temporary; saving is not connected.
   [Server] Temporary profile ready for <имя> (MemoryOnly)
   [Client] Profile received: schema 1, team 1, storage MemoryOnly
   ```

   Порядок серверных строк может отличаться. Старые сообщения про подключение Rojo заменены диагностикой этапа 3.
3. Чтобы проверить запросы вручную, открой **Window → Script → Command Bar** в текущем интерфейсе Studio и выбери **клиентский** контекст во время Play. Введи команду и выполни её через **Ctrl+Enter** или кнопку Run:

   ```lua
   game:GetService("ReplicatedStorage").GameNetwork.Request:FireServer({action = "GetState"})
   ```

4. В клиентском Explorer открой Players → свой игрок → PlayerScripts → GameClient → main только для просмотра, если нужно проверить расположение клиента. Профиль в Explorer не хранится: он находится в таблицах сервера.
5. Для снятия и повторной экипировки тестового питомца выполни в клиентском Command Bar этот блок. Он запоминает ID из ответа, снимает питомца, затем возвращает его в команду с интервалом между запросами:

   ```lua
   local net = game:GetService("ReplicatedStorage").GameNetwork
   local connection
   connection = net.Response.OnClientEvent:Connect(function(result)
       if not result.ok or not result.state then return end
       connection:Disconnect()
       local id = result.state.profile.EquippedPetIds[1]
       assert(id, "Нет экипированного тестового питомца; перезапусти Play")
       task.delay(0.3, function()
           net.Request:FireServer({action = "UnequipPet", petId = id})
           task.wait(0.3)
           net.Request:FireServer({action = "EquipPet", petId = id})
       end)
   end)
   net.Request:FireServer({action = "GetState"})
   ```

   В Output клиента ожидается команда сначала 0, затем 1. Это пока проверка данных; UI и видимые питомцы появятся позже.
6. Отдельно, спустя хотя бы секунду, отправь поддельный запрос:

   ```lua
   game:GetService("ReplicatedStorage").GameNetwork.Request:FireServer({action = "GetState", userId = 123})
   ```

   Ожидается `Request rejected: InvalidRequest`. Обычный GetState после него продолжает работать.
7. Для проверки изоляции запусти сервер с двумя клиентами средствами тестирования Studio. У каждого клиента должна быть своя коллекция и один экипированный питомец. Снятие питомца в первом клиенте не меняет команду второго. Для проверки чужого ID передай его в EquipPet второго клиента: ожидается PetNotOwned.
8. Останови тест, запусти заново: профиль создаётся заново, выдаётся новый GUID. Сохранения на этом этапе отсутствуют.
9. Останови тест и сохрани рабочий MythicPets.rbxl через Studio, если изменял карту. Код сохраняй в файлах.
