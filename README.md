# MythicPets

Roblox-проект на Luau с синхронизацией кода через Rojo.

Визуальные правила проекта и виды ресурсов: [docs/visual-direction.md](docs/visual-direction.md).
Шаблон генерации референсов: [docs/reference-prompt-template.md](docs/reference-prompt-template.md).

## Требования

- Roblox Studio с плагином Rojo 7.7.1.
- Rokit; версии Rojo и Lune закреплены в `rokit.toml`.
- Git для локальной истории изменений.
- VS Code с поддержкой Luau — по желанию.

## Повторный запуск

1. Открой PowerShell и перейди в проект:

   ```powershell
   Set-Location "C:\Users\mazma\OneDrive\Desktop\robloxgm"
   ```

2. При первой настройке или после изменения `rokit.toml` установи инструменты:

   ```powershell
   rokit install
   rojo --version
   ```

   Ожидаемая версия: `Rojo 7.7.1`. Повторять `rokit init` не требуется.

3. Запусти сервер синхронизации и оставь терминал открытым:

   ```powershell
   rojo serve default.project.json
   ```

4. В Roblox Studio открой рабочий плейс `MythicPets.rbxl` из корня проекта. Это новый файл с площадкой и точкой появления. `Place2.rbxl` и `Place2-rojo-test.rbxl` использовались только для проверки совместимости.
5. Открой плагин Rojo на вкладке Plugins, укажи `localhost` и порт из терминала (обычно `34872`), нажми Connect. Проверь предложенные изменения перед применением.
6. Редактируй код в `src`, сохраняй файлы. Rojo передаёт изменения в Studio. Изменения кода вручную в Studio обратно в файлы не переносятся.
7. Для проверки нажми Play и открой Output. После изменения кода останови и снова запусти игру, чтобы проверить новый запуск скриптов.

Если плагин отсутствует, сохрани работу, закрой Studio, выполни `rojo plugin install` и открой Studio заново. Если подключение не удаётся, проверь, что `rojo serve` работает и адрес с портом совпадают.

## Завершение работы

1. Останови игру в Studio и сохрани рабочий плейс, если менял карту или другие объекты, которые не управляются Rojo.
2. Отключи плагин Rojo и останови сервер сочетанием Ctrl+C в терминале.
3. Проверь изменения через `git status` и сохрани нужные файлы коммитом. Git не делает коммиты автоматически.

## Структура

| Путь | Назначение |
|---|---|
| `src/shared` | Общие модули в `ReplicatedStorage/Shared` |
| `src/server` | Серверный код в `ServerScriptService/GameServer` |
| `src/client` | Клиентский код в `StarterPlayer/StarterPlayerScripts/GameClient` |
| `assets` | Подготовленные ресурсы; пока не подключены к Rojo |
| `docs` | Документация и решения |
| `tests` | Проверки игровых правил |
| `tools` | Вспомогательные команды |
| `default.project.json` | Правила переноса файлов в объекты Roblox |
| `rokit.toml` | Закреплённые версии инструментов |

Пустые папки попадут в Git после добавления файлов. При восстановлении проекта до заполнения `src/shared` создай эту папку вручную: она указана в конфигурации Rojo.

## Карта и сборка

Сейчас `Workspace` не описан в `default.project.json`. Карту редактируем в Studio и сохраняем в рабочем файле `MythicPets.rbxl`. Этот файл предназначен для хранения в Git.

Проверочная команда:

```powershell
rojo build default.project.json -o rojo-check.rbxl
```

Она создаёт новый плейс только из описанных в конфигурации объектов и кода. Карта из открытого окна Studio или другого `.rbxl` автоматически в него не добавляется. `rojo-check.rbxl` — временная сборка, а не рабочая карта.

Полная сборка игры из файлов потребует отдельно включить карту и ресурсы в конфигурацию. Для ближайших этапов достаточно рабочего плейса Studio и синхронизации кода.

## Что исключено из Git

Скачанные инструменты (`download`), проверочная сборка `rojo-check.rbxl`, генерируемый `sourcemap.json`, файлы блокировки Studio и тестовые плейсы `Place2.rbxl`, `Place2-rojo-test.rbxl`.

Игнорирование не удаляет файлы с диска. Рабочий плейс `MythicPets.rbxl` создан отдельно; общего запрета на `.rbxl` в `.gitignore` нет.

## Проверки этапа 3

```powershell
rokit install
.\tools\verify.ps1
```

Команда запускает тесты правил профиля, собирает код через Rojo, компилирует Luau-файлы и проверяет размещение скриптов. Lune 0.11.1 используется только для локальных проверок и работы с файлами плейсов; игру запускает Studio.

Профили пока хранятся только в памяти сервера и сбрасываются при выходе. Сохранения не подключены. Поля ресурсов и технические лимиты не означают согласованный баланс.

Инструкция проверки сервера и клиентов в Studio: [docs/stage-3-checks.md](docs/stage-3-checks.md).

`tools/create-workplace.luau` использовался один раз для создания нового плейса из проверочной сборки. Он отказывается перезаписывать существующий `MythicPets.rbxl`; повторно создавать карту при запуске не требуется.
